# 户籍关系图谱接口文档

- 所属平台：徐州数据治理应用平台
- 模块：户籍关系图谱（Graph）
- 接口版本：v1.1
- 更新日期：2026-10-22
- 后端服务：`ruoyi-admin`（Spring Boot 3.5 + Neo4j Driver）

---

## 1. 通用说明

### 1.1 服务地址

| 环境 | Base URL |
| --- | --- |
| 本地开发 | `http://localhost:8080` |
| 生产部署 | 按实际域名/IP 配置，默认端口 `8080` |

所有接口均为 `GET`，返回 `application/json;charset=UTF-8`。

### 1.2 鉴权方式

图谱接口受 Sa-Token 登录态保护，请求必须携带登录令牌。前端登录后由请求拦截器自动附加以下请求头：

| 请求头 | 是否必填 | 说明 |
| --- | --- | --- |
| `Authorization` | 是 | `Bearer <access_token>` |
| `clientid` | 是 | 客户端标识，当前平台为 `e5cd7e4891bf95d1d19206ce24a7b32e` |

获取令牌接口：

**POST** `/auth/login`

请求体（密码模式，验证码关闭时）：

```json
{
  "clientId": "e5cd7e4891bf95d1d19206ce24a7b32e",
  "grantType": "password",
  "username": "admin",
  "password": "admin123"
}
```

响应示例（仅保留关键字段）：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "expire_in": 604800,
    "client_id": "e5cd7e4891bf95d1d19206ce24a7b32e"
  }
}
```

> 验证码开启时，`/auth/login` 还需传入 `code`（验证码）与 `uuid`（`GET /auth/code` 返回的标识）。当前部署通过 `--captcha.enable=false` 关闭了验证码。

### 1.3 通用响应结构

所有接口统一使用 `R<T>` 包装：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | 业务状态码，`200` 成功；`401` 未登录/令牌失效；`500` 服务异常 |
| `msg` | string | 提示信息 |
| `data` | object | 业务数据，失败时可能为 `null` |

> 注意：鉴权失败时 HTTP 状态码仍为 `200`，需根据响应体中的 `code` 判断。

## 2. 查询个人亲属图谱

**GET** `/graph/person/direct`

查询指定身份证号人员的亲属关系图，返回节点与关系边。

### 2.1 请求参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `gmsfhm` | string | 是 | - | 人员身份证号（18 位） |
| `level` | int | 否 | `0` | 查询扩展级数，见下表 |

`level` 取值说明：

| 取值 | 含义 |
| --- | --- |
| `0` | 默认模式：配偶、父母、子女、兄弟姐妹及其配偶/子女，以及补充的祖孙、伯叔舅姑姨、侄甥、姻亲、其他亲属 |
| `1` ~ `16` | 以该人员为中心向外扩展的关联级数，超过 16 按 16 处理 |
| 负数（如 `-1`） | 不限级数，返回所有可达关联人员 |

### 2.2 请求示例

```http
GET /graph/person/direct?gmsfhm=320311193805120012&level=1
Authorization: Bearer <access_token>
clientid: e5cd7e4891bf95d1d19206ce24a7b32e
```

### 2.3 响应示例

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "hasRelation": true,
    "nodes": [
      {
        "id": "320311196308150038",
        "name": "张建国",
        "gmsfhm": "320311196308150038",
        "xbdm": "1",
        "yhzgxdm": "03",
        "center": false,
        "endpoint": false
      },
      {
        "id": "320311193805120012",
        "name": "张德福",
        "gmsfhm": "320311193805120012",
        "xbdm": "1",
        "yhzgxdm": "02",
        "center": true,
        "endpoint": false
      }
    ],
    "edges": [
      {
        "source": "320311193805120012",
        "target": "320311196308150038",
        "type": "FATHER_OF",
        "label": "父亲"
      }
    ],
    "description": "张德福 的 1 级关系"
  }
}
```

### 2.4 边界情况

| 场景 | 返回 |
| --- | --- |
| 身份证号不存在 | `hasRelation=false`，`nodes`/`edges` 为空数组，`description="未找到身份证号为 xxx 的人员"` |
| 人员存在但无亲属 | `hasRelation=true`，仅返回中心节点，`edges` 为空 |

## 3. 查询两人关系路径

**GET** `/graph/relation/path`

基于 Neo4j `shortestPath` 查询两人之间的最短亲属关系路径。

### 3.1 请求参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `from` | string | 是 | - | 人员 A 身份证号 |
| `to` | string | 是 | - | 人员 B 身份证号 |
| `level` | int | 否 | `0` | 路径最大级数，见下表 |

`level` 取值说明：

| 取值 | 含义 |
| --- | --- |
| `0` | 默认模式，最大 16 级 |
| `1` ~ `16` | 限制最短路径的最大级数 |
| 负数（如 `-1`） | 不限级数 |

### 3.2 请求示例

```http
GET /graph/relation/path?from=320311193805120012&to=320311198806100112&level=0
Authorization: Bearer <access_token>
clientid: e5cd7e4891bf95d1d19206ce24a7b32e
```

### 3.3 响应示例

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "hasRelation": true,
    "nodes": [
      {
        "id": "320311193805120012",
        "name": "张德福",

      {

        "gmsfhm": "320311198806100112",
        "xbdm": "1",
        "yhzgxdm": null,
        "center": false,
        "endpoint": true
      }
    ],
    "edges": [
      {
        "source": "320311193805120012",
        "target": "320311194103080022",
        "type": "MARRIED_TO",
```

### 3.4 边界情况

| 场景 | 返回 |
| --- | --- |
| 两人无通路 | `hasRelation=false`，`nodes`/`edges` 为空数组，`description="两人之间不存在亲属关系"` |
| 两人身份证号相同 | `hasRelation=true`，仅返回 1 个节点，`description="张三 与 张三 是同一个人"` |
| 任一身份证号不存在 | 同“两人无通路” |

## 4. 图谱统计

**GET** `/graph/stats`

用于首页数据看板，统计节点总数、关系总数、各关系类型数量及性别分布。

### 4.1 请求参数

无。

### 4.2 请求示例

```http
GET /graph/stats
Authorization: Bearer <access_token>
clientid: e5cd7e4891bf95d1d19206ce24a7b32e
```

### 4.3 响应示例

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "nodeCount": 34,
    "edgeCount": 56,
    "relationTypes": [
      { "type": "MARRIED_TO", "label": "配偶", "count": 16 },
      { "type": "FATHER_OF", "label": "父亲", "count": 15 },
      { "type": "MOTHER_OF", "label": "母亲", "count": 15 },
      { "type": "GRANDCHILD_OF", "label": "孙子/孙女", "count": 5 },
      { "type": "IN_LAW", "label": "姻亲", "count": 4 },
      { "type": "GREAT_GRANDCHILD_OF", "label": "曾孙/曾孙女", "count": 1 }
    ],
    "genderStats": [
      { "code": "1", "label": "男", "count": 20 },
      { "code": "2", "label": "女", "count": 14 }
    ]
  }
}
```

> `relationTypes` 按关系数量倒序排列，仅返回实际存在的关系类型。

## 5. 数据结构

### 5.1 GraphResult

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `hasRelation` | boolean | 是否查询到关系/人员 |
| `nodes` | GraphNode[] | 节点列表 |
| `edges` | GraphEdge[] | 关系边列表 |
| `description` | string | 关系描述文本，可直接用于页面提示 |

### 5.2 GraphNode

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 节点唯一标识，等于身份证号 |
| `name` | string | 姓名 |
| `gmsfhm` | string | 公民身份号码 |
| `xbdm` | string | 性别代码：`1` 男、`2` 女，其他为未知 |
| `yhzgxdm` | string \| null | 与户主关系代码，如 `02` 表示户主；路径查询中为 `null` |
| `center` | boolean | 是否为查询中心人员（直系亲属查询） |
| `endpoint` | boolean | 是否为路径端点人员（两人关系查询） |

### 5.3 GraphEdge

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `source` | string | 起点身份证号 |
| `target` | string | 终点身份证号 |
| `type` | string | 关系类型代码，见第 6 节 |
| `label` | string | 关系类型中文名称 |

### 5.4 GraphStats

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `nodeCount` | long | 人员节点总数 |
| `edgeCount` | long | 关系边总数 |
| `relationTypes` | RelationTypeCount[] | 各关系类型统计 |
| `genderStats` | GenderCount[] | 性别分布统计 |

`RelationTypeCount`：`{ "type": string, "label": string, "count": long }`

`GenderCount`：`{ "code": string, "label": string, "count": long }`

## 6. 关系类型字典

当前图谱共 12 种关系类型。除标注“无向”的类型外，其余均为有向关系，`source` 为关系起点。

| type | label | 方向 | 语义 / 起点说明 | 代差 |
| --- | --- | --- | --- | --- |
| `FATHER_OF` | 父亲 | 有向 | 父亲 → 子女 | 1 |
| `MOTHER_OF` | 母亲 | 有向 | 母亲 → 子女 | 1 |
| `MARRIED_TO` | 配偶 | 无向 | 夫妻关系 | 0 |
| `SIBLING_OF` | 兄弟姐妹 | 无向 | 同辈旁系 | 0 |
| `GRANDPARENT_OF` | 祖辈 | 有向 | 祖辈 → 孙辈 | 2 |
| `GRANDCHILD_OF` | 孙子/孙女 | 有向 | 孙辈 → 祖辈（内孙） | 2 |
| `MATERNAL_GRANDCHILD_OF` | 外孙/外孙女 | 有向 | 外孙辈 → 祖辈 | 2 |
| `GREAT_GRANDCHILD_OF` | 曾孙/曾孙女 | 有向 | 曾孙辈 → 祖辈 | 3 |
| `PARENT_SIBLING_OF` | 伯叔舅姑姨 | 有向 | 伯叔舅姑姨 → 侄甥辈 | 1 |
| `NEPHEW_OF` | 侄甥 | 有向 | 侄甥辈 → 伯叔舅姑姨 | 1 |
| `IN_LAW` | 姻亲 | 无向 | 女婿/儿媳、公婆岳父母、姻亲配偶等 | 0 |
| `OTHER_RELATIVE` | 其他亲属 | 无向 | 堂表兄弟姐妹及其他亲属 | 0 |

> 说明：`GRANDCHILD_OF`、`MATERNAL_GRANDCHILD_OF`、`GREAT_GRANDCHILD_OF`、`NEPHEW_OF` 的边方向为“晚辈 → 长辈”，前端渲染时按长辈方向展示箭头；`MARRIED_TO`、`SIBLING_OF`、`IN_LAW`、`OTHER_RELATIVE` 为无向边，不显示箭头。

## 7. 错误码

| code | HTTP | 说明 | 处理建议 |
| --- | --- | --- | --- |
| `200` | 200 | 成功 | - |
| `401` | 200 | 认证失败，无法访问系统资源 | 重新登录获取 `access_token`，并检查 `clientid` 请求头 |
| `500` | 200/500 | 服务内部异常（如 Neo4j 连接失败） | 检查后端日志与 Neo4j 服务状态 |
| 参数校验失败 | 200 | 缺少必填参数或参数类型错误 | 按接口参数表补全参数 |

未登录响应示例：

```json
{
  "code": 401,
  "msg": "认证失败，无法访问系统资源",
  "data": null
}
```

## 8. 调用示例

### 8.1 curl

```bash
# 1. 登录获取令牌
TOKEN=$(curl -s -X POST 'http://localhost:8080/auth/login' \
  -H 'Content-Type: application/json' \
  -d '{"clientId":"e5cd7e4891bf95d1d19206ce24a7b32e","grantType":"password","username":"admin","password":"admin123"}' \
  | jq -r '.data.access_token')

# 2. 查询直系亲属
curl -s 'http://localhost:8080/graph/person/direct?gmsfhm=320311193805120012&level=1' \
  -H "Authorization: Bearer $TOKEN" \
  -H 'clientid: e5cd7e4891bf95d1d19206ce24a7b32e'

# 3. 查询两人关系
curl -s 'http://localhost:8080/graph/relation/path?from=320311193805120012&to=320311198806100112&level=0' \
  -H "Authorization: Bearer $TOKEN" \
  -H 'clientid: e5cd7e4891bf95d1d19206ce24a7b32e'

# 4. 图谱统计
curl -s 'http://localhost:8080/graph/stats' \
  -H "Authorization: Bearer $TOKEN" \
  -H 'clientid: e5cd7e4891bf95d1d19206ce24a7b32e'
```

### 8.2 前端调用（项目内封装）

```ts
import { getDirectRelatives, getRelationPath, getGraphStats } from '@/api/graph';

const direct = await getDirectRelatives('320311193805120012', 1);
const path = await getRelationPath('320311193805120012', '320311198806100112', 0);
const stats = await getGraphStats();
```

## 9. 前端展示约定

- 2D 视图统一使用矩形节点，所有节点尺寸一致（84 × 36）。
- 中心节点（`center=true`）与路径端点（`endpoint=true`）使用金色边框高亮。
- 关系按代差分层布局：祖辈在上，依次为父辈、中心人员、子辈、孙辈、曾孙辈。
- 户主节点（`yhzgxdm="02"`）姓名后自动追加“（户主）”。
- 关系称谓按性别与年龄区分展示，例如哥哥/弟弟、姐姐/妹妹、孙子/孙女、外孙/外孙女、伯/叔/舅、姑/姨等。
